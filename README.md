This repository contains the system framework, configuration files, evaluation scripts, and semantic map outputs for the paper:  
**"A LiDAR-Inertial-RTK Fusion Localization and Fruit-Tree Instance Mapping System for Tracked Inspection Robots in Non-Standardized Orchards"** (Under Review at *Computers and Electronics in Agriculture*).

---

## 1. Core Source Code Release Policy

To protect intellectual property (IP) and proprietary implementations prior to formal publication, the underlying C++ source code for the core algorithmic packages—specifically the asynchronous sequential ESIKF fusion estimator and the sub-pixel fruit-tree instance mapping node—has been temporarily withheld from this public branch.

**The full, executable ROS workspace and complete algorithmic source code will be officially open-sourced to the research community immediately upon the formal acceptance of this paper.**

## 2. Repository Structure & Quantitative Reproducibility

To assist reviewers in verifying the physical authenticity of our real-world experiments and the reproducibility of our quantitative metrics, we provide the complete engineering skeleton, hardware interfaces, actual sensor configurations, and evaluation tools. The repository is organized as follows:

### 📍 `/fast_lio_navigation`
Contains the authentic physical parameters and tuned planners used in our real-world tracked UGV autonomous navigation experiments (validating **Section 3.4** of the paper).
* **`/param`**: Highly customized configurations for undulating orchard terrains, including `teb_local_planner_params.yaml`, `costmap_common_params.yaml`, and `global_planner_params.yaml`.
* **`/maps`**: Pre-built 2D safety costmaps (`orchard_map.pgm` & `.yaml`) generated by our semantic mapping module.

### 📍 `/rtk_driver/scripts` (Evaluation Scripts)
Contains the authentic Python scripts used to process field datasets and generate the quantitative evaluations and figures presented in the paper:
* `extract_rtk_gt.py`: Extracts high-precision RTK ground truth with lever-arm extrinsic compensation.
* `simulate_signal_outage.py`: Reproduces the controlled GNSS signal degradation and outage experiments (validating **Section 3.2**).
* `eval_naive_baseline.py`: Reproduces the trajectory comparison against the "Naive RTK-LIO" baseline shown in **Table 3** and **Table 4**.
* `plot_signal_degradation.py`: Generates the spatiotemporal analysis heatmaps shown in **Figure 8**.
* `eval_nav_smoothness.py`: Evaluates navigation trajectory tracking accuracy and chassis smoothness metrics shown in **Table 8**.

### 📍 `/orchard_semantic_map`
Contains the reconstructed fruit-tree instance semantic map outputs (validating **Section 2.3.2** and **Section 3.3**):
* `tree_inventory.csv`: The extracted individual fruit-tree coordinate inventory (WGS-84 coordinates and instance IDs).
* `map.rviz`: RViz visualization configuration for displaying the semantic tree models and point cloud maps.

### 📍 `/LIO-RTK` & Hardware Drivers
Contains the core state-estimation mathematical dependencies, calibration files, and hardware drivers:
* **`/LIO-RTK/config`**: Actual sensor calibration files (`velodyne.yaml`, `localization.yaml`).
* **`/LIO-RTK/include`**: Core mathematical libraries including `ikd-Tree` and `IKFoM_toolkit` used by the front-end LIO.
* **Hardware Drivers**: Authentic drivers for the 3D LiDAR (`/lslidar_driver`), RTK receiver (`/rtk_driver`), and 10-axis IMU (`/wit_imu_driver`) deployed on our onboard Intel NUC computing platform.

## 4. Quick Start & Execution

### 4.1 Running Soft-Anchored LIO-RTK
Launch the localization and visualization interface:
```bash
# Terminal 1: Launch the LIO-RTK estimation node and RViz visualization
roslaunch fast_lio rtk_mapping.launch

# Terminal 2: Play the experimental ROS bag
rosbag play Straight-Line-0.2.bag --clock
```

### 4.2 Running Quantitative Evaluation Scripts
All evaluation scripts are located in `/rtk_driver/scripts/`:

```bash
# 1. Extract ground truth trajectory with lever-arm compensation
python3 rtk_driver/scripts/extract_rtk_gt.py --bag Straight-Line-0.2.bag

# 2. Simulate GNSS outages and degradation (Section 3.2, Table 4)
python3 rtk_driver/scripts/simulate_signal_outage.py --bag Straight-Line-0.2.bag

# 3. Evaluate trajectory against Naive RTK-LIO baseline (Table 3 & Table 4)
python3 rtk_driver/scripts/eval_naive_baseline.py

# 4. Generate signal degradation spatiotemporal heatmaps (Figure 8)
python3 rtk_driver/scripts/plot_signal_degradation.py

# 5. Evaluate autonomous corridor navigation metrics (Table 8)
python3 rtk_driver/scripts/eval_nav_smoothness.py
```
