# LIO-RTK-Orchard-Navigation

This repository contains the system architecture, hardware configurations, evaluation scripts, and semantic map datasets for the paper:  
**"A LiDAR-Inertial-RTK Fusion Localization and Fruit-Tree Instance Mapping System for Tracked Inspection Robots in Non-standardized Orchards"**.

---

## 1. Core Source Code Release Policy

To protect intellectual property (IP) and proprietary implementations prior to formal publication, the underlying C++ source code for the core algorithmic packages—specifically the asynchronous sequential ESIKF fusion estimator and the sub-pixel fruit-tree instance mapping node—has been temporarily withheld from this public branch.

**The complete, executable ROS workspace, full algorithmic C++ source packages, and launch files will be fully open-sourced to the research community immediately upon the formal acceptance of this paper.**

---

## 2. Repository Structure & Quantitative Reproducibility

To assist reviewers and readers in verifying the physical authenticity of our real-world field experiments and the reproducibility of our quantitative metrics, we provide the full engineering skeleton, authentic sensor configurations, evaluation scripts, and field datasets. The repository is organized as follows:

### 📍 `/fast_lio_navigation`
Contains the authentic physical parameters and tuned planners used in our real-world tracked UGV autonomous navigation experiments (validating **Section 3.4** of the paper).
* **`/param`**: Highly customized configurations for undulating and narrow orchard terrains, including `teb_local_planner_params.yaml`, `costmap_common_params.yaml`, and `global_planner_params.yaml`.
* **`/maps`**: Pre-built 2D safety costmaps (`orchard_map.pgm` & `.yaml`) generated by our multi-layer mapping pipeline.

### 📍 `/rtk_driver/scripts` (Evaluation Scripts)
Contains the core Python processing and analysis scripts used to parse field datasets and reproduce the evaluation metrics and figures presented in the paper:
* `extract_rtk_gt.py`: Parses NMEA-0183 GST sentences and extracts high-precision RTK ground truth with lever-arm extrinsic compensation (**Section 2.6**).
* `simulate_signal_outage.py`: Reproduces the controlled synthetic GNSS degradation scenarios (Dropout, Biased, Jumps, False-fixed) detailed in **Section 3.1**.
* `eval_naive_baseline.py`: Reproduces the comparative evaluations against FAST-LIO2, LIO-SAM, and the "Naive RTK-LIO" baseline shown in **Table 3** and **Table 4**.
* `plot_signal_degradation.py`: Generates the spatiotemporal observation quality and position uncertainty heatmaps presented in **Figure 8**.
* `eval_nav_smoothness.py`: Evaluates the global path clearance and corridor traversal metrics presented in **Table 8**.

### 📍 `/orchard_semantic_map`
Contains the final mapping outputs corresponding to **Section 3.3**:
* `tree_inventory.csv`: The final extracted semantic fruit-tree inventory containing unique tree IDs and globally referenced WGS84 coordinates (validating the results in **Table 5**).
* `map.rviz`: RViz visualization configuration for displaying the registered point cloud, extracted tree centroids, and 2D safety costmap.

### 📍 `/LIO-RTK` & Hardware Drivers
Contains the state-estimation mathematical dependencies, driver wrappers, and extrinsic calibration parameters:
* **`/LIO-RTK/config`**: Authentic multi-sensor calibration parameters and lever-arm offsets (`velodyne.yaml`, `localization.yaml`).
* **`/LIO-RTK/include`**: Mathematical foundation libraries including `ikd-Tree` and `IKFoM_toolkit` utilized by the direct LiDAR odometry module.
* **Hardware Drivers**: Authentic drivers and interface nodes for the 32-channel LiDAR (`/lslidar_driver`), dual-antenna RTK receiver (`/rtk_driver`), and 10-axis IMU (`/wit_imu_driver`) deployed on the onboard Intel NUC platform.
